Lesson 01 · Getting Started

Toolkit & Environment Setup

Before writing a single line of Kotlin, set up a professional workbench. By the end of this lesson you will have a JDK, IntelliJ IDEA, Android Studio, the Android SDK, an emulator and (optionally) a real phone — all wired together and verified.

⏱ ~60 min (mostly downloads)🎯 Beginner💻 Windows · macOS · Linux

You will be able to

  • Explain what each tool (JDK, IDE, SDK, Gradle, emulator) does
  • Install IntelliJ IDEA and Android Studio on your OS
  • Download SDK packages with the SDK Manager
  • Create and boot an Android Virtual Device
  • Run apps on a real phone over USB or Wi-Fi
  • Fix the most common setup errors yourself

1.2System requirements & virtualization

Android development is resource-hungry: the IDE, Gradle daemon and emulator each run in their own process. These are practical numbers, slightly above the official minimums:

ResourceMinimumComfortable
OSWindows 10 64-bit · macOS 12+ · 64-bit Linux (glibc 2.31+)Windows 11 · latest macOS · Ubuntu 22.04+
RAM8 GB16 GB or more
Free disk16 GB32 GB+ on an SSD (SDK + emulator images + Gradle caches grow over time)
CPU64-bit x86_64 with virtualization, or Apple Silicon (ARM)Modern 8-core CPU
Screen1280 × 8001920 × 1080 or larger

Check that hardware virtualization is enabled

The Android Emulator runs a full virtual phone. Without hardware acceleration it is unusably slow (or refuses to start).

Open Task Manager → Performance → CPU and look for Virtualization: Enabled. If it says Disabled, reboot into your BIOS/UEFI and enable Intel VT-x / AMD-V (SVM).

Then enable the Windows Hypervisor Platform (WHPX) feature, which the emulator uses for acceleration:

Alternative: install the Android Emulator hypervisor driver from the SDK Manager (SDK Tools tab) — useful on AMD machines where WHPX is unavailable.

Nothing to do. macOS uses Apple's built-in Hypervisor.framework. On Apple Silicon (M1–M4) make sure you later pick arm64-v8a system images — they are fast; x86 images are not supported.

The emulator uses KVM. Check support and install it (Ubuntu/Debian shown):

Android Studio also needs a few 32-bit libraries on some distributions; see the official Linux install notes if the emulator fails to start.

ℹ️
What is JAVA_HOME?

JAVA_HOME is an environment variable that tells tools such as Gradle where the JDK lives. Installers usually set it. If a tool complains “JAVA_HOME is not set”, point it to the JDK folder (the one containing bin/java), e.g. C:\Program Files\Eclipse Adoptium\jdk-21… or /Library/Java/JavaVirtualMachines/temurin-21.jdk/Contents/Home.

1.4Install IntelliJ IDEA

For lessons 02–15 we write plain Kotlin programs with a main function. IntelliJ IDEA, made by JetBrains (the creators of Kotlin), has first-class Kotlin support built in — no plugin required.

  1. Install the JetBrains Toolbox App (recommended)Download it from jetbrains.com/toolbox-app. Toolbox installs and updates IntelliJ IDEA (and Android Studio, if you like) with one click. Alternatively download IntelliJ IDEA directly from jetbrains.com/idea — the free edition covers everything in this course.
  2. Create a Kotlin projectFile → New → Project, choose Kotlin on the left. Name it kotlin-playground, build system Gradle, Gradle DSL Kotlin, JDK 21 (IntelliJ can download one for you from this dropdown). Tick Add sample code.
  3. Run the sampleOpen src/main/kotlin/Main.kt and click the green ▶ gutter icon next to fun main(). The output appears in the Run tool window at the bottom.
  4. Add more filesRight-click src/main/kotlin → New → Kotlin Class/File → File. Each file may have its own main; run whichever you want from its gutter icon.

1.5Install Android Studio

Download the latest stable release from developer.android.com/studio. Avoid Canary/Beta builds while learning — tutorials and error messages match the stable channel.

  1. Run the downloaded android-studio-*-windows.exe.
  2. Keep both components ticked: Android Studio and Android Virtual Device.
  3. Use the default install folder (C:\Program Files\Android\Android Studio). Avoid paths with non-ASCII characters or spaces for the SDK folder later.
  4. Finish, then launch Android Studio from the Start menu.

Prefer winget? winget install Google.AndroidStudio

  1. Open the downloaded .dmg — pick the Mac with Apple chip build on M-series Macs.
  2. Drag Android Studio into Applications.
  3. Launch it. If macOS warns that it was downloaded from the internet, click Open.

Prefer Homebrew? brew install --cask android-studio

On Ubuntu you can also use sudo snap install android-studio --classic.

1.6Tour of the Android SDK & SDK Manager

Open Tools → SDK Manager (or More Actions → SDK Manager on the Welcome screen). It has two important tabs:

SDK Platforms

One entry per Android version (API level). Each contains android.jar — the APIs you compile against. Install the latest stable API; the final project uses compileSdk = 36 (Android 16). Tick Show Package Details to also pick emulator system images.

SDK Tools

Versioned tools shared by all platforms. Make sure these are installed: Android SDK Build-Tools, Android SDK Platform-Tools (adb, fastboot), Android Emulator, Android SDK Command-line Tools (latest).

Sdk/ ├── build-tools/36.x.x/ # aapt2, d8, apksigner, zipalign ├── cmdline-tools/latest/ # sdkmanager, avdmanager ├── emulator/ # the Android Emulator ├── platform-tools/ # adb, fastboot ├── platforms/android-36/ # android.jar for API 36 └── system-images/ # emulator OS images

Put adb on your PATH

Not required for Android Studio itself, but very handy: adb lets you install apps, read logs and open a shell on the device from any terminal.

Then run source ~/.zshrc and adb version.

Then run source ~/.bashrc and adb version.

🧠
compileSdk vs minSdk vs targetSdk
compileSdk
Which android.jar you compile against — the newest APIs you can call.
minSdk
The oldest Android version that can install your app. Lower = more devices, more compatibility code.
targetSdk
The version whose behaviour you have tested against. Google Play requires a recent value each year.

1.7Create an Android Virtual Device (emulator)

  1. Open the Device ManagerView → Tool Windows → Device Manager (or the phone icon in the right toolbar), then click + → Create Virtual Device.
  2. Pick hardwareChoose a phone profile such as Pixel 8 or Medium Phone. Profiles with the Play Store icon include Google Play services.
  3. Pick a system imageChoose the newest stable API with Google APIs or Google Play. ABI: x86_64 on Intel/AMD, arm64-v8a on Apple Silicon. Click the download icon next to it.
  4. Verify configurationName it (e.g. Pixel 8 API 36). Under Additional settings you can raise RAM or internal storage if your machine has plenty.
  5. Boot itPress ▶ next to the device. The first boot takes a minute; later boots use a Quick Boot snapshot and take seconds.

Emulator tips
  • The ⋯ Extended controls panel simulates GPS location, battery level, phone calls, SMS, camera and rotating the device.
  • Drag an .apk file onto the emulator window to install it; drag any file to copy it to Download/.
  • Use Cold Boot (Device Manager → ⋮) if the emulator gets into a weird state; Wipe Data resets it to factory.

1.8Run on a real Android device

A physical phone is faster than any emulator and shows real-world performance, touch feel and sensors.

Step 1 — Enable Developer options

  1. Open Settings → About phone.
  2. Tap Build number seven times (on some brands it is under Software information). You'll see “You are now a developer!”.
  3. Go back to Settings → System → Developer options and turn on USB debugging.

Step 2 — Connect

  1. Plug the phone in with a data cable (some cheap cables only charge).
  2. On the phone, accept the “Allow USB debugging?” dialog and tick Always allow from this computer.
  3. Windows only: if the phone does not appear, install the Google USB Driver (SDK Manager → SDK Tools) for Pixels, or your phone maker's USB driver.
  4. Linux only: you may need udev rules — install android-sdk-platform-tools-common on Ubuntu/Debian, then add yourself to the plugdev group.
  1. Computer and phone must be on the same Wi-Fi network.
  2. On the phone: Developer options → Wireless debugging → On.
  3. In Android Studio's device dropdown choose Pair Devices Using Wi-Fi, then on the phone tap Pair device with QR code and scan.
  4. Or pair from the terminal with a pairing code:

Step 3 — Verify

If the state says unauthorized, unlock the phone and accept the debugging prompt. If it still fails, use Developer options → Revoke USB debugging authorizations and reconnect.

Let's prove the whole toolchain works end to end.

  1. New ProjectOn the Welcome screen click New Project and choose the Empty Activity template (the one with the Compose logo).
  2. Configure
    Name

  3. Wait for Gradle syncThe status bar shows progress. The first sync downloads Gradle and dependencies and can take several minutes. Subsequent syncs are fast thanks to caches.

Recommended settings

  • Settings → Editor → General → Auto Import: tick Add unambiguous imports on the fly and Optimize imports on the fly.
  • Settings → Editor → Inlay Hints → Kotlin: enable type hints — they show inferred types, which is a superb learning aid.
  • Settings → Tools → Actions on Save: enable Reformat code and Optimize imports.
  • Tools → Kotlin → Show Kotlin Bytecode → Decompile lets you see the Java equivalent of any Kotlin file — a great way to understand what the compiler generates.

1.12Troubleshooting common setup errors

SymptomLikely causeFix
Gradle sync failed: Could not resolve …No internet, proxy or firewallCheck Settings → HTTP Proxy; retry with File → Sync Project with Gradle Files. Behind a company proxy, also configure ~/.gradle/gradle.properties.
SDK location not foundlocal.properties missingOpen the project from Android Studio (it writes the file), or add sdk.dir=/path/to/Sdk.
Unsupported class file major version 65 / JDK mismatchGradle running on a different JDK than expectedSettings → Build Tools → Gradle → Gradle JDK: pick the bundled jbr-21.
Emulator: x86_64 emulation requires hardware accelerationVirtualization disabledEnable VT-x/AMD-V in BIOS and WHPX / KVM (section 1.2).
Emulator is extremely slow or blackLow RAM, software graphicsClose other apps; in AVD settings set Graphics: Hardware; use a smaller screen device.
adb devices shows nothingCharge-only cable, missing driver, USB modeTry another cable/port; install the OEM driver; set USB mode to File transfer.
INSTALL_FAILED_UPDATE_INCOMPATIBLEAn app with the same ID but different signature is installedadb uninstall com.example.app, then run again.
Build runs out of memoryGradle heap too smallAdd org.gradle.jvmargs=-Xmx4g to gradle.properties.
🩺
The universal fix list

When something is weird and you don't know why, try in this order: 1. Sync Project with Gradle Files → 2. Build → Clean Project → 3. File → Invalidate Caches → Invalidate and Restart → 4. delete the project's .gradle/ and build/ folders → 5. read the full error in the Build window (click the top-most red line).

1.13Exercises

Exercise 1 — Environment checklist Easy

Run each command in a new terminal and write down the version it prints: java -version, adb version, kotlinc -version (if you installed it). Then in Android Studio open Help → About and note the IDE version.

There's no single right answer — the goal is to confirm every tool is on your PATH. If a command is “not recognized”, revisit the PATH steps above and open a new terminal.

Exercise 2 — Two devices at once Medium

Create a second AVD with a tablet profile and a different API level. Boot both, then run HelloAndroid on each from the device dropdown. Use adb -s <serial> shell getprop ro.build.version.release to print each device's Android version.

Exercise 3 — Read the build output Challenge

In HelloAndroid, open the Terminal tool window and build a debug APK with the Gradle wrapper. Find the generated APK file and install it manually with adb.
