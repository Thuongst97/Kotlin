Collections

Real programs work with groups of data: a list of tasks, a set of tags, a map from IDs to users. Kotlin's collection library is one of its superpowers — dozens of expressive operations that replace most hand-written loops.

⏱ 60 min🎯 Beginner → Intermediate▶ All examples are runnable

You will be able to

  • Pick between List, Set, Map and arrays
  • Explain read-only vs mutable collections
  • Transform with map, filter, flatMap, associate
  • Group, partition, sort, chunk and zip data
  • Aggregate with sumOf, fold, maxByOrNull
  • Use sequences for lazy, efficient pipelines

7.1The collection family

List

Ordered, indexed, duplicates allowed.
listOf("a", "b", "a")

Set

Unique elements; default implementation keeps insertion order.
setOf("a", "b")

Map

Key → value pairs, unique keys; keeps insertion order.
mapOf("a" to 1)

Read-only vs mutable

Each kind exists in two flavours. The read-only interface (List, Set, Map) has no methods to change the content; the mutable one (MutableList…) adds add, remove, set, clear.

Read-onlyCreateMutableCreate
List<T>listOf(), emptyList()MutableList<T>mutableListOf(), ArrayList()
Set<T>setOf()MutableSet<T>mutableSetOf(), hashSetOf()
Map<K, V>mapOf()MutableMap<K, V>mutableMapOf(), hashMapOf()
💡
Expose read-only, keep mutable private

A common pattern in classes (and in Android ViewModels): store a private val _items = mutableListOf<Item>() and expose val items: List<Item> get() = _items. Callers can read but not modify your state.

7.2Lists

⚠️
val + mutable list

val todo = mutableListOf(…) can still be modified — val only stops you from assigning a different list. Conversely, var list = listOf(…) lets you replace the whole list with a new read-only one (list = list + "x"). In UI state, the second style (new immutable instances) is preferred.

7.4Arrays

Arrays have a fixed size and mutable elements. In everyday Kotlin, prefer lists. Use arrays for vararg, Java APIs that require them, and performance-critical numeric code: IntArray, DoubleArray… map to JVM primitive arrays (int[]) with no boxing.

7.5Transformations: map, filter & friends

Collection operations take a lambda — a block of code in { }. Inside a single-parameter lambda, the parameter is called it (lesson 10 covers lambdas properly). Every operation returns a new collection; the original is untouched.

7.6Aggregation, searching & sorting

☕
Coming from Java Streams

No .stream() and .collect(Collectors.toList()) — operations are called directly on collections and return lists. groupBy, partition, associate, sumOf cover most Collectors. The difference: Kotlin collection operations are eager; for laziness use sequences (next section).

7.7Sequences: lazy evaluation

Each step of a collection chain creates a full intermediate list. A Sequence instead processes elements one at a time through the whole chain, and stops as soon as it has enough. Use it for long chains over large data, or for infinite streams.

⚖️
When to use which

For small collections (hundreds of items) and short chains, plain lists are simpler and often faster. Reach for sequences with large data, many chained steps, short-circuiting terminals like first/take, or generators.

7.8Building collections

Need to build a list with some logic, but want a read-only result? buildList, buildSet and buildMap give you a mutable builder inside the block and return a read-only collection.
