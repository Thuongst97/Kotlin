How to use this page

Option A (recommended): create a new project and type each milestone yourself, running the app at every checkpoint. Option B: clone the repository, open final-project/TaskFlow in Android Studio and read along. Either way, do the stretch goals at the end — they're where the learning sticks.

Milestone 1 — Create the project & configure Gradle

Goal: an empty Compose app that builds with all the libraries we'll need.

  1. New projectAndroid Studio → New Project → Empty Activity. Name TaskFlow, package com.kotlinacademy.taskflow (use your own domain for a real app), Minimum SDK API 26, build language Kotlin DSL.
  2. Version catalogReplace gradle/libs.versions.toml with the catalog below. Android Studio will highlight newer versions — upgrading is fine, but keep Kotlin, the Compose compiler plugin and KSP aligned.
  3. Root build & settingsDeclare every plugin once in the root build.gradle.kts with apply false.
  4. App build scriptApply the plugins, set SDK levels, Java 17, Compose, Room schema directory and dependencies.
  5. Sync & runClick Sync Now, then ▶ Run. You should see the template's “Hello Android!”.
✅
Checkpoint

./gradlew assembleDebug succeeds. If sync fails, read the first error in the Build window — usually a typo in an alias (libs.androidx.room.runtime maps to androidx-room-runtime in the catalog).

Goal: a tasks table, a DAO that exposes a Flow, and mappers between the database and domain models.

Mapping functions are extension functions (lesson 10) that keep each layer's model private to that layer:

💡
Why store priority as an Int?

If Room stored the enum's name, renaming MEDIUM to NORMAL later would break every existing row. Storing a stable number (weight) decouples the database from Kotlin names.

Look closer
  • @Upsert returns -1 for updates — the repository handles it so callers always get the real id.
  • Import is idempotent: remote ids are stored, so importing twice adds nothing.
  • The try/catch lists exactly the expected failures and deliberately lets CancellationException through (lesson 13).

Milestone 8 — Reminder notifications with WorkManager

Goal: when a task with “Remind me” is due, a notification appears at 9:00 — even if the app was closed.

🧪
Test a reminder without waiting a day

Temporarily change REMIND_AT to a time a few minutes from now, set the due date to today and enable the reminder. Watch it in App Inspection → Background Task Inspector, then close the app and wait for the notification.

Milestone 9 — Tests, CI & release

Goal: automated proof that TaskFlow works, on every push, plus a signed release bundle.

Coding conventions, enforced

TaskFlow follows the official conventions and rule set. ktlint checks formatting against the .editorconfig; detekt checks complexity, naming, error handling and coroutine misuse with a few Compose-aware overrides. CI runs both before building.

The repository's GitHub Actions workflow runs the build, unit tests and instrumented-test compilation on every push and uploads the debug APK as an artifact, so you can download and install a build without opening Android Studio.
