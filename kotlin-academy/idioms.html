Errors, Delegation & Idioms

The difference between code that works and code that's a pleasure to maintain. Handle failures deliberately, reuse behaviour with delegation, and learn the idioms experienced Kotlin developers reach for every day.

12.1Exceptions

Exceptions signal that something went wrong and unwind the call stack until caught. In Kotlin, try is an expression, and there are no checked exceptions — the compiler never forces you to catch or declare them.

⚠️
Catch narrowly

Catch the specific exceptions you can actually handle. Catching Exception or Throwable everywhere hides bugs — and in coroutines it can swallow CancellationException, breaking cancellation (lesson 13).

12.3Result & runCatching

Result<T> holds either a value or an exception. runCatching { } runs a block and captures whatever it returns or throws. It makes failure an ordinary value that callers can't forget about.

🧭
Exceptions, Result, null or sealed class?
  • Programming errors (bugs, broken invariants) → throw (require/check). Let them crash in development.
  • “Not found” with no further detail → return null (findUser(id): User?).
  • Expected failures from I/O (network, parsing) → Result at the boundary.
  • Domain failures the UI must distinguish → your own sealed type (LoginResult.WrongPassword, .Locked…).

12.4Closing resources with use

Files, streams, database cursors and sockets must be closed even when an exception happens. use { } works on anything Closeable/AutoCloseable and closes it for you — Kotlin's version of Java's try-with-resources.

12.5Class delegation with by

Want to implement an interface by forwarding most calls to an existing object and overriding only a few? class X(inner: I) : I by inner generates all the forwarding methods. Composition with no boilerplate.

12.6Delegated properties

val x by something hands the property's get/set logic to a delegate object. The standard library provides lazy (lesson 06), observable, vetoable and map-backed properties — and you can write your own. Compose's var count by remember { mutableStateOf(0) } is exactly this feature.

12.7Operator overloading & destructuring

Mark a function operator with a predefined name and Kotlin maps the symbol to it: a + b → a.plus(b), a[i] → a.get(i), x in c → c.contains(x), f() → f.invoke(), a < b → a.compareTo(b) < 0, val (x, y) = p → component1(), component2().

⚠️
Overload only where the meaning is obvious

vector + vector and money + money are great. user + group is a puzzle. If a reader has to look up what + means, use a named function.

12.9Exercises

Exercise 1 — Safe division Easy

Write fun safeDivide(a: Int, b: Int): Result<Int> that fails with a clear message on division by zero. Print results for (10, 2) and (1, 0) using fold.

Exercise 2 — Money type Medium

Create data class Money(val cents: Long, val currency: String) with plus (requires same currency), times(Int), compareTo and a nice toString. Sum a list of Money with reduce.

Exercise 3 — Logging delegate Challenge

Write a reusable delegate fun <T> logged(initial: T): ReadWriteProperty<Any?, T> that prints every read and write with the property name.
