Lesson 09 · Object-Oriented Kotlin

Data, Enum, Sealed & Object

Kotlin ships specialized kinds of classes for the most common modelling jobs. Master these five and you can model almost any domain — and every Android screen state — precisely and safely.

⏱ 50 min🎯 Intermediate⭐ Used constantly in Android

You will be able to

  • Model values with data class and copy
  • Represent fixed sets with enum class
  • Model state machines with sealed types
  • Create singletons with object
  • Write factories in companion objects
  • Wrap primitives safely with value classes

9.1Data classes

A class whose main job is to hold data. Add data and the compiler generates, from the primary-constructor properties: equals()/hashCode() (compare by value), a readable toString(), copy(), and componentN() functions for destructuring.

💡
Immutable data + copy = predictable state

Use val properties in data classes. To “change” something, create a modified copy. Jetpack Compose and StateFlow detect changes by comparing old and new values with equals — mutating an object in place would go unnoticed, copying never does.

ℹ️
Rules & gotchas
  • The primary constructor needs at least one val/var parameter.
  • Only properties in the primary constructor take part in equals/toString/copy; properties declared in the body are ignored.
  • Data classes can't be open/abstract, but they can implement interfaces and extend sealed classes.
  • copy is shallow: a copied object shares the same nested lists.

9.2Enum classes

An enum defines a fixed set of named constants. Each constant is an object; enums can have properties, methods, and even per-constant behaviour.

Prefer entries over the older values(), which allocates a new array on every call.

9.3Sealed classes & interfaces

An enum has a fixed set of instances. A sealed type has a fixed set of subtypes — each of which can carry different data. All direct subtypes must be declared in the same module and package, so the compiler knows the complete list and can check that when handles every case.

This is the idiomatic way to model UI state, results and events:

🛡️
Why this beats flags

Compare with class State(val isLoading: Boolean, val items: List<String>?, val error: String?): nothing stops isLoading = true and error = "x" at the same time. With a sealed type, impossible states are impossible to represent. And when you add a new state (e.g. Offline), every when that doesn't handle it stops compiling — the compiler gives you a to-do list.

9.4object: singletons & anonymous objects

An object declaration defines a class and its single instance at once. It's created lazily and thread-safely on first access.

⚠️
Singletons are global state

Mutable singletons make code hard to test and reason about. Use object for stateless helpers and constants; for shared services (database, network), prefer one instance created and injected by a DI framework (lesson 18).

9.5Companion objects

Kotlin has no static keyword. Members that belong to the class rather than to instances go into a companion object. Typical uses: factory functions, constants, and parsing.

For Java callers, add @JvmStatic to companion functions to make them real static methods, and use const val or @JvmField for constants.

9.6Value classes: type-safe wrappers for free

Is fun transfer(from: Long, to: Long, amount: Long) safe? One swapped argument and you send money the wrong way. A value class wraps a single value in its own type; at runtime the wrapper is usually erased, so there's no allocation cost.

9.7Nested vs inner classes

A class declared inside another is nested by default: it does not hold a reference to the outer instance (like Java's static nested class). Mark it inner to access the outer instance's members.

Inner classes keep the outer object alive. On Android, an inner class or lambda capturing an Activity and outliving it is a classic memory leak — prefer nested classes unless you really need the outer instance.

9.8Exercises

Exercise 1 — Immutable shopping cart Easy

Model CartItem(name, price, qty) and Cart(items: List<CartItem>) as data classes. Write Cart.add(item) returning a new cart (merging quantity when the name exists) and a computed total.

Exercise 2 — Traffic light state machine Medium

Create enum class Light(val seconds: Int) with RED(30), GREEN(25), YELLOW(5) and a next() function using an exhaustive when. Simulate 4 transitions starting at RED.

Exercise 3 — Payment methods Challenge

Model payments as a sealed interface: Card(last4, brand), BankTransfer(iban), Wallet(provider), and Cash (a data object). Write fee(payment, amountCents): card 2.9% + 30¢, bank transfer flat 50¢, wallet 1.5%, cash free. Write describe that masks the IBAN except its last 4 characters.
