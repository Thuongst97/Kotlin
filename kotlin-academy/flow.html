Lesson 14 · Advanced Kotlin

Flow, StateFlow & Channels

A suspend function returns one value. A Flow emits many values over time: database rows that change, search results as the user types, a download's progress. Flow is how modern Android apps move data from the data layer to the UI.

⏱ 60 min🎯 Advanced📦 kotlinx-coroutines 1.10

You will be able to

  • Create cold flows and collect them
  • Transform with map, filter, debounce…
  • Handle errors with catch, retry, onCompletion
  • Combine streams with combine, zip, flatMapLatest
  • Hold UI state in StateFlow; send events with SharedFlow
  • Convert with stateIn and pick the right sharing policy

14.1Cold flows: builders & collection

A Flow<T> is cold: the code inside the flow { } builder doesn't run until someone calls a terminal operator like collect — and it runs again, from the start, for every collector. Think of it as a recipe, not a running process.

14.2Intermediate operators

Intermediate operators return a new flow without collecting it. Many mirror collection operations; others deal with time.

OperatorWhat it does
map, filter, take, dropSame as on collections, element by element
transform { emit(…) }Emit zero, one or many values per input
onEach { }Side effect for each value (logging)
distinctUntilChanged()Skip values equal to the previous one
debounce(ms)Emit only after the source is quiet for ms (search boxes)
scan(initial) { acc, v -> }Running accumulation, emitting each intermediate result
flowOn(dispatcher)Run the upstream on another dispatcher
🧭
Context preservation & flowOn

A flow's emissions happen in the collector's coroutine context — you may not call withContext around emit. To run producing code elsewhere, put .flowOn(Dispatchers.IO) after it: everything above flowOn runs on IO, everything below (and the collector) stays where it was.

14.3Errors, retries & completion

catch only sees exceptions from operators above it, not from the collect block below. To also handle errors thrown by your collection logic, move it into onEach and finish with .catch { }.collect() or launchIn(scope).

14.4Combining flows

zip

Pairs values 1:1 — the 1st with the 1st, the 2nd with the 2nd. Ends with the shorter flow.

combine

Whenever any source emits, recomputes from the latest value of each. Perfect for “filters + data → UI state”.

flatMapLatest

For each new value, start a new inner flow and cancel the previous one. Perfect for search queries.

14.5StateFlow: observable state

A StateFlow is a hot flow that always holds one current value. New collectors immediately receive the latest value; equal consecutive values are skipped (it uses equals, which is why immutable data classes are a perfect fit). It's the standard holder for UI state in a ViewModel.

💡
Always update with update { }

_state.value = _state.value.copy(…) is a read-then-write that can lose updates when called from several coroutines. _state.update { it.copy(…) } retries atomically.

14.6SharedFlow, stateIn & sharing policies

A SharedFlow is a hot flow that broadcasts values to all current collectors without holding a current value (configurable replay). Use it for one-off events (“show snackbar”). stateIn/shareIn turn a cold flow into a hot one shared by many collectors.

SharingStartedUpstream runs…Use for
Eagerlyimmediately, forever (while scope lives)Always-needed data
Lazilyfrom the first subscriber, foreverExpensive data needed once started
WhileSubscribed(5_000)while someone collects, plus a 5 s grace periodAndroid UI state — survives rotation (no restart), stops in background

14.7Channels

A Channel is a coroutine-safe queue: send suspends when full, receive suspends when empty. Each value is delivered to exactly one receiver (unlike SharedFlow, which broadcasts). Use channels for producer/consumer pipelines and work distribution; in app code, flows are usually the better fit.

14.9Exercises

Exercise 1 — Ticker Easy

Write fun ticker(periodMs: Long): Flow<Int> that emits 0, 1, 2… forever. Collect only the first 5 values and print them as a list.

Exercise 2 — Download progress Medium

Model a download as Flow<DownloadState> where DownloadState is sealed: Progress(percent), Done(file), Failed(reason). Emit progress 0, 25, 50, 75, 100, then Done. Use transformWhile to stop collecting after a terminal state.

Exercise 3 — Search ViewModel without Android Challenge

Build a SearchModel(scope) with query: MutableStateFlow<String> and results: StateFlow<List<String>>: debounce 200 ms, ignore queries shorter than 2 chars (empty results), use flatMapLatest to call a fake suspending search. Simulate typing.
