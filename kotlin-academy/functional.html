Lambdas, Extensions & Scope Functions

In Kotlin, functions are values: you can store them in variables, pass them to other functions and return them. This lesson unlocks the style you've already seen in map { … } — and the features that make Jetpack Compose and Kotlin DSLs possible.

⏱ 60 min🎯 Intermediate▶ All examples are runnable

You will be able to

  • Write lambdas and read function types like (Int) -> String
  • Create higher-order functions and use trailing lambdas
  • Use function references (::name) and closures
  • Add behaviour to existing types with extensions
  • Choose correctly between let, run, with, apply, also
  • Explain inline, non-local returns and lambdas with receivers

10.1Lambdas & function types

A lambda is an anonymous function written in braces: parameters, an arrow, then the body. The last expression is the return value. Its type is a function type such as (Int, Int) -> Int.

10.2Higher-order functions & trailing lambdas

A higher-order function takes functions as parameters or returns one. When the last parameter is a function, you can pass the lambda outside the parentheses — the trailing lambda syntax that makes list.filter { … } and Compose's Column { … } read so naturally.

10.3Function references & closures

Already have a named function that fits? Pass it with :: instead of wrapping it in a lambda. Lambdas also capture variables from their surrounding scope (a closure) and can even modify captured vars.

10.4Extension functions & properties

Extensions add functions or properties to a type you don't own — String, List, Android's Context — without inheritance. Inside, this is the receiver object. Most of Kotlin's standard library (map, filter, trim…) is written as extensions.

🔬
How extensions really work

An extension doesn't modify the class. It compiles to a static function taking the receiver as its first parameter: isPalindrome(String $this). Consequences: extensions can't access private members, and they're resolved statically by the declared type — no polymorphism. If a class has a member with the same signature, the member always wins.

10.5Scope functions: let, run, with, apply, also

Five tiny standard-library functions that run a block in the context of an object. They differ in two ways: how you refer to the object (it or this) and what they return.

FunctionObject asReturnsTypical use
letitlambda resultNull checks x?.let { }, transforming a value
runthislambda resultConfigure + compute a result in one block
with(x)thislambda resultCall many methods on one object (non-extension)
applythisthe object itselfConfiguring/initializing an object
alsoitthe object itselfSide effects: logging, validation
🧭
Quick decision guide
  • Null check on a value? → ?.let
  • Setting up an object's properties? → apply
  • Logging or validating mid-chain? → also
  • Need a computed result from an object? → run / with

Don't nest them deeply — three levels of it/this is unreadable. When in doubt, a plain local val is fine.

10.6inline functions & non-local returns

Each lambda passed to a normal function becomes an object. Marking a higher-order function inline makes the compiler copy its body and the lambda's body into the call site — zero overhead. That's why map, filter, let and forEach are inline.

A bonus: inside a lambda passed to an inline function, a bare return returns from the enclosing function (a non-local return). To return from just the lambda, use a label: return@forEach.

Related modifiers: noinline (keep one lambda parameter as an object, e.g. to store it) and crossinline (forbid non-local returns from a lambda that is called from another context). reified type parameters (lesson 11) also require inline.

10.7Lambdas with receivers — the secret of DSLs

The type StringBuilder.() -> Unit is a function that runs as if it were an extension on StringBuilder: inside the lambda, this is a StringBuilder. That's how apply, buildString and Compose's layout scopes work. Lesson 15 builds a complete DSL with this.

10.8Exercises

Exercise 1 — Your own filter and map Easy

Implement myFilter and myMap as generic extension functions on List<T> using a loop.

Exercise 2 — Function composition Medium

Write an infix function andThen that composes (A) -> B with (B) -> C into (A) -> C. Use it to build a text normalizer pipeline: trim → lowercase → collapse spaces.

Exercise 3 — Memoize Challenge

Write fun <A, R> memoize(f: (A) -> R): (A) -> R that caches results in a map captured by the returned lambda. Count how many times the real function runs.
