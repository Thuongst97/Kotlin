Lesson 05 · Kotlin Fundamentals

Functions

Functions are the building blocks of every Kotlin program. Kotlin makes them unusually expressive: default and named arguments replace overloads and builders, single-expression functions remove ceremony, and functions can live anywhere — top level, inside classes, even inside other functions.

⏱ 45 min🎯 Beginner▶ All examples are runnable

You will be able to

  • Declare functions with parameters and return types
  • Write single-expression functions
  • Use default and named arguments
  • Accept a variable number of arguments with vararg
  • Create infix, local and recursive functions
  • Explain Unit, Nothing and tailrec

5.1Declaring functions

  • Parameters always need explicit types; they are read-only (val).
  • A function with a block body must declare its return type (unless it's Unit) and use return.
  • Functions can be declared after they're used — order in the file doesn't matter.

5.2Single-expression functions

When the body is a single expression, replace { return … } with =. The return type can then be inferred.

💡
Style

Prefer the expression form for short functions. For public library APIs, still write the return type explicitly — it documents the contract and prevents accidental type changes.

5.3Default & named arguments

Parameters can have default values, and callers can pass arguments by name in any order. Together they replace Java's telescoping overloads and many builder classes.

📖
Name your booleans

sendEmail(user, true, false) is unreadable. sendEmail(user, urgent = true, copyToSelf = false) explains itself. Use named arguments whenever a literal's meaning isn't obvious.

☕
Coming from Java

Java callers don't see default values. Annotate the function with @JvmOverloads to generate the overloads Java needs. You'll see this on Android custom views: class MyView @JvmOverloads constructor(context: Context, attrs: AttributeSet? = null).

5.5Early returns, Unit and Nothing

A function that “returns nothing” actually returns Unit. A function that never returns normally (always throws or loops forever) returns Nothing — and the compiler uses that knowledge for flow analysis.

The standard library has TODO("reason"), which returns Nothing — perfect for stubbing functions you haven't written yet.

5.6Infix & local functions

Infix functions (one parameter, marked infix) can be called without dot and parentheses. You've already used one: to in "a" to 1. Local functions are declared inside another function and can access its variables — perfect for helpers nobody else needs.

fun Int.pow(…) is an extension function — it adds a function to an existing type. Lesson 10 covers extensions in depth.

5.7Recursion & tailrec

A recursive function calls itself. Each call uses stack memory, so very deep recursion throws StackOverflowError. If the recursive call is the very last operation, mark the function tailrec and the compiler rewrites it into a loop.

ℹ️
Why isn't factorial tail-recursive?

After factorial(n - 1) returns, we still multiply by n — the call isn't the last operation. The compiler warns if you put tailrec on a function that isn't truly tail-recursive.

5.8Designing good functions

  • Do one thing. If the name needs “and”, split it.
  • Name with verbs for actions (loadUser, sendEmail) and with nouns or is/has for queries (userCount, isValid).
  • Keep them short — a screenful at most. Extract local or private helpers.
  • Prefer pure functions (same input → same output, no side effects). They're trivial to test.
  • Few parameters. Beyond 3–4, group them into a data class (lesson 09).
  • Fail fast with require(…) on invalid input (lesson 12).

5.9Exercises

Exercise 1 — Password strength Easy

Write fun isStrong(password: String, minLength: Int = 8): Boolean: true if the password is at least minLength long and contains at least one digit and one uppercase letter. Use any { it.isDigit() }.

Exercise 2 — Flexible greeting Medium

Write a single function greeting that supports all these calls: greeting("Ada") → Hello, Ada!; greeting("Ada", "Hi") → Hi, Ada!; greeting("Ada", shout = true) → HELLO, ADA!; greeting("Ada", "Hey", "?") → Hey, Ada?.

Exercise 3 — Fibonacci, three ways Challenge

Implement fib(n) (fib(0)=0, fib(1)=1) recursively, with tailrec, and iteratively. Why is the naive recursive version so slow for n = 40?

The naive version recomputes the same values exponentially many times (~2ⁿ calls). The other two are linear.
