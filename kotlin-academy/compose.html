Lesson 17 · Android with Kotlin

Jetpack Compose UI

Compose is Android's modern toolkit for building UI — entirely in Kotlin. You describe what the screen should look like for the current state, and Compose updates it whenever that state changes. No XML layouts, no findViewById, no manual view updates.

⏱ 75 min🎯 Intermediate📦 Compose BOM 2025.06

You will be able to

  • Write and preview composable functions
  • Hold state with remember / mutableStateOf
  • Hoist state for reusable, testable components
  • Lay out UI with modifiers, Row, Column, Box
  • Show long lists efficiently with LazyColumn
  • Theme with Material 3 and run side effects safely

In the old View system you created widgets once and then mutated them (textView.text = "…"). In Compose you write functions that emit UI for a given state. When state changes, Compose calls the affected functions again — this is recomposition — and updates only what changed.

📏
Rules of composables
  • Names are PascalCase nouns (they describe UI, not actions): TaskItem, not showTask.
  • They return Unit and emit UI by calling other composables.
  • They can run often, in any order, and may be skipped — so no side effects in the body (no network calls, no writes to variables outside).
  • Accept a modifier: Modifier = Modifier parameter and apply it to the root element.

17.2State & recomposition

Compose only redraws when it observes a change in State objects. mutableStateOf(x) creates an observable value; remember keeps it across recompositions (otherwise it would reset every time the function runs).

17.3State hoisting: stateless components

State hoisting means moving state up to the caller: the component receives the value and an event callback instead of owning the state. Stateless composables are reusable, previewable and testable. Rule: state goes down, events go up.

Stateful (hard to reuse)
Hoisted (reusable)

TaskFlow uses this pattern at screen level: TasksScreen (stateful: gets the ViewModel) calls TasksContent (stateless: only parameters). Tests and previews use TasksContent directly.

17.4Layouts & modifiers

Column

Children stacked vertically. verticalArrangement, horizontalAlignment.

Row

Children side by side. Modifier.weight(1f) shares remaining space.

Box

Children on top of each other. contentAlignment, Modifier.align.

Modifiers decorate or configure an element: size, padding, background, click handling, semantics. They're applied in order, so order matters:

🧭
Modifier order in one sentence

.padding(16.dp).background(Red) → transparent margin, then red; .background(Red).padding(16.dp) → red area with content inset. Read modifiers top to bottom as “wrap the element in…”.

Units

Use dp (density-independent pixels) for sizes and spacing and sp (scales with the user's font size setting) for text. Material 3 typography styles already use sp.

17.5Lists with LazyColumn

A Column composes all its children. LazyColumn composes only the visible items (like RecyclerView, without adapters). Always provide a stable key so Compose can track items when the list changes.

LazyRow scrolls horizontally; LazyVerticalGrid and LazyVerticalStaggeredGrid build grids. stickyHeader may require @OptIn(ExperimentalFoundationApi::class) depending on your Compose version.

17.8Side effects

Sometimes a composable must do something outside of drawing: collect events, show a snackbar, start an animation, register a listener. Use the effect APIs, which tie the work to the composable's lifecycle:

APIUse when
LaunchedEffect(key) { }Run suspend code when the composable enters, and restart when key changes (collect one-off events, show a snackbar)
rememberCoroutineScope()Launch coroutines from event callbacks (e.g. scroll to top on button click)
DisposableEffect(key) { onDispose { } }Register/unregister non-Compose listeners
derivedStateOf { }Compute state from other state, recomposing only when the result changes
SideEffect { }Publish Compose state to non-Compose code after every successful recomposition

17.10Accessibility & performance

♿ Accessibility

  • Give meaningful icons a contentDescription; use null for decorative ones.
  • Touch targets ≥ 48dp (Material components handle this).
  • Use Modifier.selectable(role = Role.RadioButton) / toggleable so whole rows are clickable and announced correctly.
  • Test with TalkBack and with the largest font size.

⚡ Performance

  • Keys in lazy lists; remember expensive calculations.
  • Pass immutable data (data classes with val, List) so Compose can skip unchanged composables.
  • Read rapidly changing state (scroll offset) as late as possible, e.g. in lambdas or derivedStateOf.
  • Measure release builds, not debug: debug Compose is much slower.

17.11Exercises

Exercise 1 — Tip calculator Easy

Build a screen with a bill amount field, tip percentage chips (10/15/20%), a “round up” switch and the computed tip and total. All state in the composable with rememberSaveable.

Exercise 2 — Hoist it Medium

Refactor the tip calculator into a stateless TipCalculatorContent(state: TipState, onAmountChange, onPercentChange, onRoundUpChange) plus a small stateful wrapper. Add two @Previews: empty and filled-in.

rememberSaveable can store a custom class if it is @Parcelize (as here) or if you write a Saver. Or move the state into a ViewModel — the topic of lesson 18.

Exercise 3 — Photo gallery grid Challenge

Show 60 colored tiles in a LazyVerticalGrid(GridCells.Adaptive(96.dp)). Tapping a tile marks it selected (checkmark overlay). Show “n selected” in the top bar with a “Clear” action. Make sure selection survives rotation.
