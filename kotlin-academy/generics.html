Generics

Generics let you write code once and use it with many types — safely. You've been using them since lesson 07 (List<String>). Now you'll write your own, and finally understand what out, in and reified mean.

⏱ 45 min🎯 Intermediate → Advanced▶ All examples are runnable

You will be able to

  • Write generic classes, interfaces and functions
  • Restrict type parameters with upper bounds and where
  • Explain covariance (out) and contravariance (in)
  • Use star projections <*>
  • Understand type erasure
  • Use inline + reified to access types at runtime

11.1Generic classes & functions

Without generics you'd write IntBox, StringBox… or use Any and cast everywhere. A type parameter (by convention a single capital letter like T) is a placeholder that the caller fills in.

11.2Upper bounds & constraints

<T : Comparable<T>> means “any type T, as long as T is comparable to itself”. Inside the function you can then use everything the bound provides. For multiple bounds, use a where clause.

The default upper bound is Any?, so a plain T may be nullable. Write <T : Any> to require non-null types.

11.3Variance: out and in

A Cat is an Animal. Is a Box<Cat> a Box<Animal>? It depends on what the box does with T.

out T — covariant

The class only produces T (returns it). Producer<Cat> is a Producer<Animal>. Example: Kotlin's read-only List<out E>.

in T — contravariant

The class only consumes T (takes it as a parameter). Consumer<Animal> is a Consumer<Cat>. Example: Comparator<in T>.

T — invariant

Reads and writes T. No subtyping relationship. Example: MutableList<E>.

🎭
Memory hook: PECS → “out produces, in consumes”

A vending machine of cola (produces cola) can be used wherever “a vending machine of drinks” is expected — out. A recycling bin that accepts any bottle can be used wherever “a bin for glass bottles” is expected — in.

11.4Type erasure & reified

On the JVM, generic type arguments are erased at runtime: a List<String> and a List<Int> are both just List. So if (x is T) doesn't compile in a normal generic function. An inline function with a reified type parameter keeps the real type, because the body is copied to each call site where the type is known.

🤖
Where you'll see reified on Android

viewModel<TaskViewModel>(), hiltViewModel<T>(), context.getSystemService<NotificationManager>(), Json.decodeFromString<Task>(json) and composable<TaskRoute> { } in Navigation are all reified generic functions.
