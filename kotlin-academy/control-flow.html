Lesson 04 · Kotlin Fundamentals

Control Flow

Make decisions with if and when, repeat work with loops, and iterate over ranges. In Kotlin, if and when are expressions — they produce values — which changes how you write code.

⏱ 40 min🎯 Beginner▶ All examples are runnable

You will be able to

  • Use if as a statement and as an expression
  • Replace if-else chains with when
  • Create ranges with .., ..<, downTo, step
  • Loop with for, while, do-while, repeat
  • Control loops with break, continue and labels

4.1if / else

The classic form works as you'd expect. The twist: if is an expression, so it returns a value — the last expression of the chosen branch. That's why Kotlin has no ternary a ? b : c operator.

ℹ️
When used as an expression, else is required

The compiler must know which value to produce in every case: val x = if (ok) 1 does not compile.

4.2when — the super-powered switch

when matches a value against branches and runs the first one that matches. No break needed, no fall-through bugs.

when without a subject

💡
Exhaustiveness

When when is used as an expression, it must cover every case. For enum and sealed types (lesson 09), the compiler checks all cases are handled without needing else — so adding a new case later produces compile errors exactly where you need to update code. This is one of Kotlin's most valuable safety features.

4.4for loops

Kotlin's for iterates over anything that provides an iterator: ranges, strings, arrays, collections, maps. There is no C-style for (int i = 0; i < n; i++) — use a range instead.

The for loop over a range compiles to the same fast counting loop as in Java — no list or iterator object is created.

4.5while, do-while & repeat

Use while when you don't know in advance how many iterations you need. do-while runs the body at least once — handy for input validation. repeat(n) is the simplest way to do something n times.

ℹ️
Scope detail

Notice that roll is declared inside the do body but used in the while condition. Kotlin allows this specifically for do-while.

4.6break, continue & labels

break exits the nearest loop, continue skips to its next iteration. To affect an outer loop, mark it with a label (name@) and refer to it with break@name.

💡
Prefer functions over labels

Labeled breaks are sometimes the clearest solution, but often extracting the nested loop into a function and using return reads better. And many loops disappear entirely once you learn collection operations (lesson 07): the example above becomes (1..9).firstNotNullOfOrNull { … }.

4.7Exercises

Exercise 1 — FizzBuzz with when Easy

For numbers 1 to 15 print Fizz for multiples of 3, Buzz for multiples of 5, FizzBuzz for both, otherwise the number. Use when without a subject.

Order matters: the % 15 branch must come first, because when takes the first match.

Exercise 2 — Letter grades Easy

Write fun grade(score: Int): Char returning A (90–100), B (80–89), C (70–79), D (60–69), F (0–59). Use when with ranges. For anything outside 0..100 throw IllegalArgumentException.

Exercise 3 — Prime numbers Medium

Print all prime numbers below 50. A number n > 1 is prime if no number from 2 to √n divides it. Use a labeled continue or a helper function.

Exercise 4 — Number guessing game Challenge

In IntelliJ, pick a secret number with (1..100).random() and loop until the user guesses it, printing “Too high” / “Too low”. Count attempts. Ignore input that isn't a number (hint: readln().toIntOrNull() ?: continue).
